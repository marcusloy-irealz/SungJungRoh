I · Why your screen accepts input and gives nothing real back

Think about the screen you deployed this morning. A visitor can type into it, tap it, filter it, and it responds instantly. It is also, in a specific sense, pretending. Everything it shows comes from sample numbers written into the code, so no matter what the visitor asks, the answer was decided before they arrived.

What was actually missing

Three things live behind the glass in a working product, and this morning’s screen has none of them.

Data that is true at this moment. Not a list you typed, but a number that changes while the page is open, arriving from somewhere that knows.

Something that computes. A rule, a lookup or a model that turns what the user asked into an answer nobody wrote down in advance. This is the part the industry sells as Algorithm-as-a-Service, and it is what makes a product a service rather than a page.

Somewhere to keep a secret. The moment you use a service that knows who you are, you hold a credential, and a credential cannot live in a browser.

What today adds, and what it does not
Today you add the first and the third: live data from a service that publishes it, and a private place for the credential that gets you in. Your product stops inventing and starts reporting.
The second one, the model, is tomorrow’s work. Wiring a model into your product uses the identical pattern you learn today: a key in an environment variable, a call from a function, an answer returned to the page. On Day 2 an agent calls the /api functions you deploy today as its tools. Learn the pattern on bus arrivals, where the right answer is standing at the kerb and you can check it with your own eyes, before you point it at a model whose answers you cannot check so easily.
Principle Learn the wiring on data you can verify by looking out of the window. When the screen says four minutes and the bus arrives in four minutes, you know the whole chain works, and that certainty is worth more this afternoon than a cleverer feature.

II · An API is an address that answers in a format a program can read

There is less mystery here than the acronym suggests. When you open a web page, a server sends back something arranged for a human eye. When your code calls an API, a server sends back the same kind of thing arranged for a program: labelled fields, no decoration, ready to be picked apart.

The four parts of any request
AddressWhich service, and which question of it. …/v3/BusArrival asks about buses.
ParametersThe specifics, after a ?. BusStopCode=01012 says which stop you mean.
HeadersFacts about the request rather than the question, including who is asking. LTA wants AccountKey here.
MethodWhat kind of act it is. Everything today is GET, which means fetch this and change nothing.
Two things come back: a status code, a three-digit number saying how it went, and a body, which is the answer itself. Section VI is about reading both.
What the answer looks like
{
  "BusStopCode": "01012",
  "Services": [
    {
      "ServiceNo": "7",
      "NextBus":  { "EstimatedArrival": "2026-09-09T14:22:31+08:00",
                    "Load": "SEA", "Type": "DD" },
      "NextBus2": { "EstimatedArrival": "2026-09-09T14:31:07+08:00",
                    "Load": "SDA", "Type": "SD" }
    }
  ]
}
This shape is called JSON, and it is the whole vocabulary you need. Braces hold labelled fields, square brackets hold lists, and you reach a value by naming the path to it. Notice that LTA gives you a timestamp, not a number of minutes: turning one into the other is your code’s job, and it is the first thing that will look wrong on screen.
Principle The field names in that answer are facts, not guesses. Call the endpoint once, look at what actually comes back, and paste those real lines into your prompt. An agent asked to guess the path will invent something reasonable, and reasonable is not the same as correct.

Which way the request travels, and why only one way works

Prof. Roh’s Interactive Explainer—
—
The browser rule that surprises people. A page is not allowed to read a response from another site unless that site explicitly permits it, by sending a header that says so. LTA sends no such header. Worse, because your call carries the AccountKey header, the browser sends a silent permission request of its own first, and LTA refuses it with a 403 and no permission header, so your real request never leaves the browser at all. Even without the header, the browser would not let your page read LTA’s reply. This is a browser protection, not an LTA fault, and it exists precisely because pages should not be able to quietly read other people’s services.
Why the detour solves both problems at once. Your page calls /api/bus, which is your own address, so there is no permission question to answer. Your function then calls LTA from a server, where headers are private and browser rules do not apply. One small change of route, and both the secrecy problem and the permission problem disappear together.

III · What LTA DataMall gives you, and what it asks in return

What you can read
The Land Transport Authority publishes the network as it is running right now. Bus arrivals refresh every twenty seconds. Alongside them sit carpark availability across HDB, LTA and URA sites, traffic incidents, train service alerts, and the location of every electric vehicle charging point. Today you use exactly one of these, and the rest are there when your product needs them.
The same credential for everybody. There is no developer key and production key to choose between, and no upgrade to ask for. Every key is the same kind, each person has their own, and LTA’s terms set a ceiling of ten million calls a day per key, which LTA may change or enforce without warning. A room of thirty refreshing all afternoon does not come close to it.
What you owe them
AttributionMandatory. A visible source notice with a link to the licence has to appear in your deployed app. There is a copyable line in section VII, ready to paste.
Commercial useAllowed, both by the API terms and by the Singapore Open Data Licence. You may build a business on this.
Never imply endorsementThe Singapore Open Data Licence version 1.0 forbids suggesting official status or LTA endorsement. This one catches people at the naming stage, so choose a name that is clearly yours.
Your key is yours aloneEach person requests their own key and keeps it secure and confidential. LTA’s terms require this, so do not share it, even with teammates.
Free means free of charge It does not mean free of obligation. The attribution line is not decoration and takes thirty seconds to add, so add it while you are building rather than promising yourself you will add it before the demonstration.

The error that will cost you an hour, and the one that saves it

Different failures, different codes
Almost every service answers a missing credential with 401, which says plainly what is wrong. LTA does not, and its exact behaviour hands you a free diagnostic. These are real responses, checked live on 24 September 2026.
What you sentCodeBody
No AccountKey header at all404The requested API was not found
Header with an empty value, e.g. code that falls back to ''404the same as no header
Header present, wrong key401nothing at all, an empty body
Variable never set, so your code sends the word undefined401identical to a wrong key, which is the trap below
Mis-cased path, or the old BusArrivalv2404the same as a missing key
BusStopCode missing or wrongly capitalised403an HTML Access Denied page
Why the shaded row matters most. If your Vercel variable was never saved, or was saved and never redeployed, then process.env.LTA_ACCOUNT_KEY is undefined. JavaScript does not drop that header: it sends the nine-letter word undefined, and LTA answers 401, byte for byte the same as a genuinely wrong key. So the commonest failure of the afternoon and the one everybody guesses first look identical from the outside, which is why the function has to say which it was.
Read the code, then act
404The header never arrived, arrived empty, or the path is wrong. Check, in this order: is the header spelled AccountKey, one word, because accountkey is fine but Account-Key is a different header; does it carry a value at all; is the path spelled with the documentation’s capitals, because /v3/Busarrival is a 404 even with a correct key. Plain http is not a cause: LTA redirects it to https and fetch follows.
401Some value arrived and LTA refused it. Two different faults land here and you cannot tell them apart from the outside, so read /api/health first. If keyConfigured is false, the variable is missing or you never redeployed. If it is true, the value itself is wrong, so re-copy it from the email and watch for a trailing space.
403An Access Denied page means the stop code never arrived. The parameter must be spelled BusStopCode exactly, with those capitals.
Getting a 401 after a string of 404s is still progress: the address and the header name are now right, and the whole chain from your page to your function to LTA is connected. What remains is the value, and keyConfigured tells you whether the value is wrong or simply absent.
Principle An error message is a claim the system makes about itself, and systems are often unhelpful about their own failures. Learn what your service does when it is unhappy, because the textbook meaning of a code is not always the local one.

IV · What a key actually is, and why anyone would want yours

An API key is not quite a password. A password proves you are you, so that a service can show you your own things. A key is closer to a name badge worn by your software: it tells the provider which caller this is, so they can count the calls, apply the limits, and switch you off if you misbehave.

Why anybody would take it

Nobody steals an LTA key because they are desperate to know when the 174 arrives. They take it for three other reasons, and all three apply to a project built in a day.

To spend what is yours. A key carries a quota. Someone else’s traffic on your key exhausts your limit, and your product stops working with no fault of its own.

To act in your name. Every call made with your key is recorded as yours. If it is used to hammer a government service, the record says you did it.

Because keys travel in packs. Automated scanners collect them wholesale from public code. A key that works is worth trying against other services, and the person who finds yours is a script, not a person who read your project and admired it.

The key names this course uses
LTA_ACCOUNT_KEYToday. Transport data.
GEMINI_API_KEYThe model. AI Studio creates one for you the first time you accept its terms, and puts it in the Secrets panel of any app that uses Gemini. If you already have one that starts AIza, make a new one, because Gemini is retiring that kind.
ONEMAP_TOKENIf you add a map. Expires every three days, which is a diary entry, not a bug.
DATA_GOV_SG_API_KEYOptional. A free data.gov.sg Developer key doubles its limits, and travels in the x-api-key header.
Use these exact names. Consistent naming across the room means anyone at another table can read your function and know immediately what it needs, and it means my worked examples paste into your project without editing.
Principle A credential is scoped power: who is calling, for what, with what limit, and until when. You will meet this idea again tomorrow, when an agent calls your /api functions as its tools, and it will matter far more then than it does today.

Where a key leaks, and who ends up holding it

Prof. Roh’s Interactive Explainer—
Click any row to see what that choice actually does. —
The second row is the one that catches careful people. Putting a key in a .env file feels like exactly the responsible thing to do, and for a server variable it is. But a name beginning VITE_ is a specific instruction to the build tool: take this value and write it into the JavaScript the browser downloads. The file is private and the value is not. If a variable is a secret, its name must never start with VITE_, and it must be read by a function rather than by a page.
The test that settles it Ask one question of any variable: does the browser need to know this? A colour, a title, a public map style, yes. A credential, never. If the browser does not need it, it belongs on the server, and there is no middle case.

The rules that keep a key private, and the one people get backwards

The ruleWhy it is written this way
1Never type a key into a component, and never paste one into a prompt.Both end up somewhere permanent. Code goes to the browser and the repository; a prompt goes into a conversation you do not control, and on a free tier it may be read by a human reviewer.
2A secret’s name never begins with VITE_.That prefix is an instruction to publish the value in the browser bundle. It is the single most common way a careful builder leaks a key while believing they were being careful.
3Check .gitignore before the key arrives.It must contain .env* and !.env.example. AI Studio’s template already has both lines, but the agent can rewrite the file, so check they are still there. Do this while your repository is still boring, because the moment the key exists you will be in a hurry.
4Search the diff before you push.Look for the first eight characters of each key you actually hold. For Google that is the AQ. form AI Studio has issued since May 2026, plus the older AIza form if you still have one. Ignore hits inside words such as FAQ. Ten seconds, every push.
5If a key reaches a commit: rotate first, tidy second.This is the one people get backwards. Deleting the file does not un-publish the key, because the history keeps it and scanners have already read it. Go to the provider, revoke, issue a new one, and only then clean the repository.
6One key per person, never shared, even with teammates.LTA’s terms require you to keep your key secure and confidential, and keys are free, so there is no reason to pass one around. A shared key means a shared quota and no way to tell whose traffic caused a problem.
Principle Git history is permanent by design, and that is a feature until the day it is not. A key pushed once stays readable in the log after you delete it, which is why rule five puts revocation before tidying.

V · The same toolchain, with one new folder inside it

AGoogle AI Studiowrites the function and the screen → BGitHubkeeps the code, never the key → CVercelholds the key and runs the function
The one new idea
Put a folder called api at the root of your project, next to src and package.json rather than inside them. Any file you place in it becomes a small program that Vercel runs on its own servers whenever somebody visits the matching address. A file at api/bus.js answers at /api/bus, and that is the entire convention.
No configuration file is needed. The folder is the instruction, and it works the same way whether your project is React, plain HTML, or anything else. Next.js is the exception: it uses app/api instead. On Vercel’s import screen, Framework Preset should read Vite; if it says Node or Express, change it to Vite.
Why this changes what your product can be
Until now Vercel handed visitors a finished page and had nothing more to say. With an api folder it will also run your instructions on demand, in a place the visitor cannot see into. That private place is what makes a key safe, and tomorrow’s agent calls the functions you put there as its tools.
If you search the web for this, take care. Vercel’s own page about Vite does not mention the api folder and points readers somewhere far more complicated. The simple convention on this slide is correct and is documented on their functions pages.
Principle The front end is the part of your product the world can read, and the back end is the part it cannot. Everything you want to keep, keep on the far side of that line, and the line is drawn by which folder a file sits in.

Why you cache, and why twenty seconds is the right number

Prof. Roh’s Interactive Explainer—
—
Vercel caches no function response by default. Your static files are cached for you, but an answer from /api is not, so a page that does nothing special calls LTA on every single view. Note also that every redeploy starts the cache empty, because Vercel keeps cached answers with the deployment that produced them, so an afternoon of frequent redeploys is an afternoon of misses. One line in your function fixes it: Cache-Control: s-maxage=20, stale-while-revalidate=40. The first number says how long a copy stays fresh, and the second lets a visitor have the slightly stale copy instantly while a new one is fetched behind them.
How to prove it is working. Vercel removes s-maxage and stale-while-revalidate before the response reaches the browser, so you will never find them in the developer tools and their absence is not a bug. Read x-vercel-cache instead: MISS on the first call, HIT inside twenty seconds, STALE between twenty and sixty, which means you got the stored copy while a fresh one was fetched, and MISS again after a quiet minute. All of these mean the cache is working. Keep the developer tools’ Disable cache box unticked.

Why the product came before the agents
An agent is a model that decides which tool to call and what to pass it. Every one of those tools is a function like the one you deployed today: a key on the server, a request to a service, and an answer returned in a format a program can read. You have now built that end to end once, with an agent writing the code and you checking what it wrote.
Tomorrow’s frameworks assume you already know what a key is, where it lives, what a function does, and how to tell whether something is working. You learned all four today, on data you could check by walking downstairs.
